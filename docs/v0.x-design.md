# Frameyard Design Baseline

**Status:** Accepted
**Initial acceptance:** 2026-10-27
**Last design revision:** 2026-11-04

This document records the decisions confirmed during design sessions. It is the living product and architecture baseline; later changes revise this document explicitly rather than silently broaden the scope. Architecture decisions that changed the baseline are recorded in `docs/adr/`.

## 1. Product contract

Frameyard is a local-first, open-source framework for frontend developers and creative coders who build parameterized videos with HTML, CSS, and JavaScript. It separates reusable, prop-parameterized compositions from the timelines that assemble compositions and media into one video. AI agents can perform the same workflows on a user's behalf through an official skill.

Its differentiator is web-native authoring combined with deterministic, frame-accurate output and an explicit timeline model—not a React-centric composition model or a feature-for-feature clone of an existing NLE.

The target use cases are product demos, social clips, animated diagrams, data visualizations, karaoke-style subtitles, personalized videos, and long-form edits up to roughly 60 minutes. Professional collaborative editing, cloud production, and broadcast workflows remain outside the target audience.

The core success criterion is an end-to-end example in which a developer can:

1. Create reusable HTML compositions with a fixed duration and a format they either declare or inherit from the project.
2. Animate them with HTML, CSS, SVG, and, where needed, a seek-safe controller for Canvas 2D and WebGL.
3. Supply JSON props and synchronized audio.
4. Assemble compositions and local media into a timeline with tracks, clips, trims, layers, and nested timelines.
5. Preview and scrub the timeline interactively.
6. Render it reproducibly to MP4 without dropped frames or timing drift.
7. Render a 60-minute timeline with up to three active layers within the long-form performance target.

The agent-enabled success criterion additionally requires an agent using the official skill to create and preserve a valid source project, optionally produce local audio and transcript assets, validate and inspect the timeline and its compositions, render it, and report all resulting artifact paths without concealing validation failures or skipped visual review.

## 2. Project and authoring model

### Project

- Projects use ordinary HTML, CSS, static assets, and native JavaScript controllers, either inline in a composition fragment or in external modules.
- `fy.config.js` explicitly maps project IDs to source files. There is no directory scanning. It has three optional maps:
  - `format`: the project's fixed `width`, `height`, and `fps`.
  - `compositions`: IDs mapped to `.html` composition fragments.
  - `timelines`: IDs mapped to JSON timeline documents.
- `format` is required when a project has timelines. Every timeline uses it. It also fills `width`, `height`, and `fps` for animated compositions that omit them; a declared value always wins. A composition that declares an `fps` must share the project frame rate exactly; a different size is fitted and transformed by the clip. A composition that declares neither `duration-in-frames` nor `fps` is static; it uses width and height, declared or inherited, and ignores the inherited fps. A composition that declares no dimensions in a project without `format` cannot render and fails with `COMPOSITION_FORMAT_UNRESOLVED`.
- Composition and timeline IDs share one namespace so `render <id>`, `check <id>`, and `still <id>` are unambiguous. The config rejects duplicates.
- A project may contain any number of compositions and timelines.

### Composition

- A composition is a partial HTML fragment with one top-level `<fy-composition>` root. The framework wraps it in the document shell, import map, sizing style, and host runtime at serve and render time. `width`, `height`, and `fps` are optional and inherit from the project `format` when absent; declared values win. `width` and `height` are declared together or not at all. Props cannot change metadata.
- A composition that declares neither `duration-in-frames` nor `fps` is static: it has no frame clock, is captured once in its initial state, and renders to a PNG. Its controller may `mount()` and validate props, but `update()` is not called and frame-state variables are not set. CSS animations and transitions are paused at time 0 with a warning; `data-fy-anim-*`, `<video>`, `<audio>`, and `<fy-transcript>` are errors. `fps` without `duration-in-frames` is an error. See [ADR 0017](./adr/0017-render-timeless-compositions-as-stills.md).
- Props blocks, the controller, and import maps are top-level siblings of the root. Top-level `<style>` and `<link rel="stylesheet">` elements are hoisted into the generated head; styles inside the root stay in the body. A fragment must not contain `<!doctype>`, `<html>`, `<head>`, `<body>`, `<title>`, `<meta>`, or the reserved `data-fy-host` attribute.
- Default props are a JSON block, `<script type="application/json" data-fy="props">`. A load's JSON props merge shallowly over the defaults, are validated as JSON, deep-frozen, and fixed for that load.
- An optional props schema is a top-level `<script type="application/json" data-fy="props-schema">` block. The supported subset is `type` (`object`, `string`, `number`, `boolean`, `array`), `properties`, `required`, `default`, `enum`, `description`, and `items`. Schema defaults fill missing values, document defaults override schema defaults, and user props override both. `check`, `still`, and `render` validate resolved props before Chromium; the host applies the same defaults and validation. Errors use `PROPS_SCHEMA_INVALID` and `PROPS_SCHEMA_INVALID_SCHEMA`.
- Props bind into the document through explicit `data-fy-*` attributes: `data-fy-text`, `data-fy-attr-*`, `data-fy-class-*`, `data-fy-if`, and `data-fy-repeat`. Primitive top-level props are also exposed as `--fy-prop-<name>` CSS custom properties. Bindings apply once per load; props are immutable.
- CSS and the Web Animations API are the animation language. `data-fy-anim-start`, `data-fy-anim-duration`, and `data-fy-anim-easing` schedule one animation per element in composition frames. `data-fy-anim-preset` adds named `fade`, `fade-up`, `fade-down`, `slide-left`, `slide-right`, `scale-in`, and `blur-in` entrance presets with the same scheduling attributes.
- An optional composition controller is declared with `<script type="text/fy-controller">`. It is either inline source or an external module referenced by `src`; a composition has exactly one controller. It may export `mount`, `update`, `dispose`, and `validateProps`; at least one is required. The controller is the only executable code in the document.
- Static composition includes are implemented. A composition includes a project partial with `<fy-include src="..." props="...">`; a partial is one `<fy-partial>` root with optional scoped props, schema, and direct inline styles. Included bindings see only the partial's props, included styles are wrapped in `@scope (...) to (...)`, and includes are static: no conditionals, loops, or remote files. Partials are project files, not `fy.config.js` entries. Included controllers are an accepted design and land in the controller slice. See [ADR 0030](./adr/0030-reuse-composition-fragments-with-scoped-includes.md).
- `fy` is the authoring namespace: `fy-composition`, `fy-transcript`, `data-fy-*`, `--fy-*`, and `text/fy-controller`. `frameyard` remains the product, package, CLI, config, manifest, server-route, import-specifier, and error-code namespace.
- User controllers are native JavaScript. The framework itself is authored in TypeScript and ships declarations, but 0.6 does not transpile user TypeScript.

### Timeline

- A timeline is a versioned JSON document. It references compositions and nested timelines by project ID and media clips by project-relative path.
- A timeline has a project-fixed format, an ordered list of tracks, and a list of clips. It may declare a `background` color and an optional `durationInFrames`.
- Tracks are `video` or `audio`. Video tracks composite from bottom to top; audio tracks mix. Each clip belongs to exactly one track. Clips on the same track cannot overlap unless a timeline-level `transitions` entry explicitly pairs them; clips on different tracks can. Touching endpoints are allowed but are not a transition. A transition's window is the overlap, and its declared geometry is `from.start < to.start < from.end < to.end`. See [ADR 0019](./adr/0019-make-same-track-overlap-the-transition-window.md).
- A clip has an ID, a track, a source, a timeline start, a source in-point, a duration, and clip-specific presentation settings. Source in-point, duration, and timeline start are integer project frames.
- Clip sources are:
  - a composition, identified by its project ID;
  - a nested timeline, identified by its project ID;
  - a local video, image, or audio asset.
- A composition clip fixes props for that instance and may trim the composition's source range. The same composition may appear multiple times with different props, source ranges, transforms, and audio settings. A clip whose composition source is static behaves like an image: it must declare `duration`, must use `sourceIn: 0`, has no intrinsic source duration, and contributes no audio or transcripts. The renderer captures one transparent PNG per composition/props pair and reuses it across segments.
- A nested timeline clip is a visual and audio source. It uses the project format, trims with the same source in-point and duration, contributes its audio, and is rendered as a group so parent opacity, transform, and blend mode apply to the whole nested result. A blend mode inside a nested timeline sees only that timeline's own backdrop; a transparent nested timeline does not see the parent's layers, and a declared nested background is part of the group. Cycles are rejected statically. Timeline clips do not override props of compositions inside the nested timeline.
- Media clips use local project files only. Video and audio durations, dimensions, and audio presence are probed before frame production. Images and static composition clips require an explicit duration. A video or audio clip that exceeds its source range is an error; an omitted duration uses the remaining source.
- Visual clips support a static transform: fit policy (`contain`, `cover`, `stretch`), an optional explicit `width`/`height` box (both fields together, mutually exclusive with `scale`) or a `scale` multiplier, pixel offset, rotation, and opacity. `fit` applies inside the box; without one, the project frame is the box. Rotation expands to the full rotated bounds rather than clipping corners.
- Visual clips may animate `x`, `y`, `scale`, `rotation`, and `opacity` with a per-channel `keyframes` object. Keys use clip-local integer frames; `0` is the clip start boundary and `duration` the end boundary. Keys hold before the first and after the last key, never extend the clip, and use a CSS timing function on the interval after each key. A keyed channel cannot also be an explicit scalar in `transform`. `opacity` and `scale` are clamped after easing; position and rotation may overshoot. `keyframes.scale` is mutually exclusive with an explicit `width`/`height` box. Timeline document version stays 1.
- A timeline may declare `transitions`: `{ from, to, kind, easing? }`, where `kind` is `dissolve` on a video track or `crossfade` on an audio track, and `easing` uses the keyframe CSS timing-function vocabulary. Both clips stay on one track and overlap; the window is `to.start .. from.end`. A dissolve composites the incoming clip above the outgoing clip with alpha `clipOpacity × eased progress`; both kinds apply equal-power audio gain (`sqrt(1 - t)` and `sqrt(t)`) to contributed audio or to the two audio clips. An overlap without a declared transition, a non-overlapping pair, reversed or contained geometry, cross-track pairs, a kind that does not match the track, duplicate participation, and unknown kinds are errors. Timeline document version stays 1.
- Visual clips may declare a static `blend` mode. It uses CSS `mix-blend-mode` semantics against the accumulated backdrop of all lower layers and the timeline background, respects the clip's source alpha, and defaults to `normal`. The supported modes are `normal`, `multiply`, `screen`, `overlay`, `darken`, `lighten`, `color-dodge`, `color-burn`, `hard-light`, `soft-light`, `difference`, and `exclusion`; `hue`, `saturation`, `color`, and `luminosity` are rejected. There are no animated blend modes, masks, filters, or other effects.
- Visual clips contribute their audio to the timeline mix unless muted: composition audio, embedded video audio, and nested timeline audio. Static compositions contribute no audio; clip audio settings on a static composition are ignored with a warning. Audio-only clips live on audio tracks and may source audio or video files. Per-clip and per-audio-track gain and mute are supported. There are no linked A/V pairs; a J/L cut is expressed by muting a video clip and placing a separate audio clip with a different source in-point.
- A timeline's duration is derived from the latest clip end. An explicit `durationInFrames` may extend it but not cut clips. A timeline with no clips is invalid; an audio-only timeline is valid and renders black video with audio.
- A timeline background is transparent by default. Blend modes see the accumulated backdrop including this background. The final video composites it over black; a nested timeline remains transparent so lower layers can show through. A composition that paints no background is transparent and may be used as an overlay.
- The preview provides a read-only timeline view and inspector: tracks, clips, keyframe markers, playhead, program monitor, diagnostics, and selected element/clip details. It is not a visual editor.

## 3. Deterministic execution

The timeline frame is the master clock. A composition's frame is derived from the clip's timeline start, source in-point, and duration. The only sources of a composition's animation state remain the integer composition frame and its immutable props.

- The runtime owns the frame clock and deterministic randomness. A composition controller imports `random("stable:key")` from `frameyard/runtime`.
- CSS `@keyframes` and Web Animations API animations are paused and positioned from the shared composition frame clock. `data-fy-anim-*` schedules one animation per element in composition frames; named presets create WAAPI animations with the same start/duration/easing contract, and the runtime maps frames to milliseconds.
- The runtime sets `--fy-frame`, `--fy-time`, `--fy-progress`, `--fy-fps`, `--fy-duration`, and `--fy-duration-frames` on the composition root every seek.
- JavaScript animation runs in the controller's `update()`, which must be synchronous and seek-safe. It cannot depend on previously visited frames.
- Declarative bindings apply once per load, before the controller mounts. Controller-created DOM is the controller's responsibility.
- Independent `requestAnimationFrame` loops, timers, CSS transitions, wall-clock reads, and unseeded randomness are not supported animation drivers.
- Timeline clip keyframes animate `x`, `y`, `scale`, `rotation`, and `opacity` from the integer clip-local frame. They are evaluated against absolute timeline frames, so segment boundaries do not change values. Preview evaluates the exact CSS timing function; production generates FFmpeg expressions and approximates the curve. Blend modes remain static. Transition progress is likewise evaluated from the absolute timeline frame; only the incoming clip carries transition alpha during a dissolve, and both kinds use the same eased progress for equal-power audio gain.
- Preview and production seek composition clips explicitly. The timeline compositor is deterministic given the captured clip frames, media frames, clip settings, and segment boundaries.
- The resolved format—declared width, height, and fps combined with the project format—is part of the immutable frame environment, alongside props and loaded assets. Layouts that use viewport units or percentages therefore depend on the resolved format by design; preview and production always resolve the same values.
- Assets, remote data, images, fonts, generated audio, transcripts, and media are resolved before frame production. Project fonts are vendored locally, recorded in `fy.fonts.json`, and injected as `@font-face` rules; the host waits for `document.fonts.ready` and fails a used face that reports an error. For a segmented timeline render, each segment's composition and nested-timeline clips are loaded and settled before that segment's frames are captured; no frame production depends on a new network request. Network is blocked during capture.
- AI model inference is never part of the loading phase, controller lifecycle, or frame production.
- The baseline supports DOM, CSS, SVG, Canvas 2D, WebGL, and frame-seeked embedded video. Canvas 2D and WebGL are drawn from the current frame by the controller.
- Embedded video and audio inside compositions are declared with `data-fy-*` attributes. The runtime loads local files, pauses them, and seeks video from the frame-derived source time before capture. An unmuted video contributes its audio track to the timeline mix unless the composition opts out or the clip mutes it.
- Transparent compositions are captured with an alpha-preserving browser background. Without that step, a top-level Chromium capture paints a white canvas and overlays become white rectangles.
- WebGL 1 and WebGL 2 canvases are captured through the normal screenshot path. Production sessions pin software WebGL so pixel output does not depend on the host GPU.
- Compositions are trusted local developer code. Frameyard does not claim to render untrusted compositions safely.

### Reproducibility guarantee

For the same timeline or composition revision, props, assets, segment plan, and frame under a pinned runtime/browser/FFmpeg environment, the captured composition frames and the deterministic timeline composite are identical. The final output is not promised to be bit-identical: encoded bytes depend on the encoder and its runtime.

Preview and production share composition behavior and capture composition frames the same way, but the timeline preview composites layers in Chromium while production composites them with FFmpeg. Small differences in scaling, alpha, and video color conversion are expected and do not violate clip-capture parity.

## 4. Preview and production rendering

Preview and production execute the same composition sources and host runtime. They differ in which component drives the frame clock, which compositor combines timeline layers, and whether frames are captured. Both also project the same timeline scene from the resolved timeline: the ordered active clips with their transition roles, composite order, frame-to-source mapping, capture modes, and presentation defaults. The scene projection is browser-safe; capture sessions, audio mixing, and both compositors stay separate.

The preview provides:

- One editor-style shell shared by the composition and timeline routes: a filterable assets list, one tabbed Source/Program monitor, a read-only timeline strip under the monitor, and a props/inspector column. Composition and timeline tiles carry resolved metadata; timeline media uses cheap image/video thumbnails. The shell follows System/Light/Dark, persists an explicit theme override, and never themes the composition or timeline canvas.
- Composition focus (`/__frameyard/`): source-first selection, JSON props editing, play/pause, frame-accurate scrubbing, frame-by-frame stepping with buttons or arrow keys, one-second jumps with buttons or Shift+arrow keys, current frame and time, audio controls, diagnostics, and a read-only element inspector with bindings, resolved values, and frame state. A static composition loads once and disables the source transport. The program monitor and timeline strip appear only after a timeline is selected.
- Timeline focus (`/__frameyard/timeline/<id>`): timeline selection, a read-only track/clip view with keyframe markers, playhead, program monitor, frame-by-frame stepping with buttons or arrow keys, one-second jumps with buttons or Shift+arrow keys, audio controls, diagnostics, and a read-only clip inspector with source, timing, presentation, and matching diagnostics. A static composition layer stays loaded and is not seeked per frame. Selecting a clip loads its source into the source monitor without moving the timeline playhead.
- The monitor tabs preserve independent playheads; selecting a clip or asset reveals the source tab, selecting a timeline reveals the program tab, and the hidden monitor pauses. Playback is exclusive across the two monitors. The shared monitor header provides Fit, 100%, staged zoom, hand/space panning, and fullscreen of the whole monitor panel.
- The timeline strip supports fit/zoom horizontal scrolling, ruler click-and-drag seeking, playhead dragging, keyframe markers, transitions, and playhead follow during playback.
- Primary selection and the primary frame are URL state. Major selections use `pushState`; frame updates use throttled `replaceState`. Source tab and clip selection are ephemeral. Both inspectors offer jump-to-start/end, a copyable `still` command, and a source link; Escape closes them. They never mutate the composition, timeline, or host props. The inspector and props editor are tabs in the same column.
- A bounded pool of active composition and nested-timeline clips. It loads clips around the playhead instead of preloading a whole long timeline.

The preview server serves each composition fragment at its project path, wraps it in the fixed document shell, and injects the framework import map and host runtime. It serves timeline documents and a timeline preview host. The timeline preview host drives active composition/nested-timeline clips, seeks them, and exposes a timeline API to the preview. Preview audio is mixed by the preview page from the resolved timeline audio clips.

Production composition rendering uses one Chromium session per composition. An animated composition seeks every frame, captures PNGs, and encodes them with FFmpeg. A static composition loads once, captures one PNG, and publishes it without FFmpeg or an encoder.

Production timeline rendering is segmented and parallel:

1. Run static timeline validation, resolve the timeline, and project the scene and render plan.
2. Split the timeline into segments at active-layer changes or a maximum segment duration. Each segment has a fixed set of visual layers and a fixed filter graph.
3. In parallel workers, capture the active composition and nested-timeline clip frames for each segment with Chromium and stream them into lossless FFV1 intermediates. `--scale` rasterizes composition viewports at the scaled pixel density and shrinks the timeline stage to the scaled format before capture, so composition PNGs, intermediates, and delivery segments are produced at the output resolution; project-pixel clip offsets and boxes are mapped into that stage, and no final encode-time scale pass runs ([ADR-0029](adr/0029-capture-renders-at-the-scaled-source-format.md)). Independent layers of one segment are captured concurrently under a global FIFO session limit, and loaded composition sessions are reused across segments when their entry, props, transparency, and capture scale match. Transparent clips are captured with an alpha-preserving background. A static composition is captured once per props variant as a transparent PNG and reused as an image layer across segments and workers. A segment with one full-frame, untransformed composition and no keyframes, blend, transition, or opacity skips the FFV1 intermediate and the composite, encoding the capture directly into the delivery segment over the timeline background. A full-frame composition base plus a static composition overlay (including a static PIP box) uses two image pipes into one FFmpeg process, which composites the background, base, and scaled overlay before the delivery encode; Windows keeps the segmented fallback. A single full-frame video with an identity transform re-encodes its source range directly, skipping the composite filter graph while keeping the delivery encoder settings.
4. Decode media clips, apply trims, fit, presentation keyframes, rotation into an expanded bound, and opacity, composite the segment with FFmpeg, and encode H.264, HEVC, or VP9.
5. Join the ordered segments with a stream copy. Segment boundaries never change frame order or timing.
6. Mix the timeline audio once with FFmpeg and mux it into the final output.
7. Publish the output atomically; delete scratch intermediates on success and failure.

The default timeline worker count is 8, configurable up to the machine's capacity. With `--encoder nvenc` the count is capped at eight concurrent encode sessions, the consumer driver limit; a larger `--workers` value produces an `ENCODER_WARNING` and the lower count. Scratch is a configurable directory with a bounded budget; it must not depend on `/tmp` alone. The reference long-form target is a representative 60-minute 1920×1080 30 fps timeline with a 50/50 composition/media split by layer-seconds, 60% one active layer, 30% two, and 10% three, rendered in 30 minutes or less on the reference machine. The 10-second benchmark measured 10.7 s for two composition captures, 35.2 MB of FFV1, and 6.1 s to composite and encode. Continuous three-layer stress runs measured 52.4 s and 58.5 s for 60 s of timeline, about 1× real time, and are documented as worst-case rather than the target workload. The representative gate measured 29.39 s for 60 s with four workers, exact 1800-frame output, and a 1080p media fast path, extrapolating to about 29.4 minutes for 60 minutes. The full 60-minute composition-only gate rendered 108,000 frames in 37.28 minutes with four workers; it is stricter than the 50/50 target mix because every frame is an HTML composition capture. Capture was 48.9% of worker time, FFV1 23.2%, composite 24.7%, and session setup 2.8%. Composition captures now stream PNG buffers into FFV1, and a segment with one full-frame, untransformed composition skips the intermediate and composite. The 60-second one-layer gate fell from 43.27 s to 27.64 s, and the full 60-minute gate completed in 19.83 minutes with eight workers; the direct output was byte-identical to the FFV1-and-composite output. Reusing loaded sessions reduced the 60-minute gate further to 18.78 minutes with eight sessions instead of 360. The two-layer PIP 60-second gate improved from 62.79 s to 59.60 s with streaming and to 43.78 s with parallel layer capture under a global session limit. A full-frame composition base plus a static composition overlay uses dual image pipes; the full-frame 60-second workload fell from 53.27 s to 34.62 s, the PIP 60-second workload from 43.78 s to 33.90 s, and the full two-layer 60-minute gates completed in 29.69 minutes (full-frame) and 25.75 minutes (PIP) with eight workers. The production representative 60-minute gate — 50/50 layer-seconds, 60/30/10 occupancy, 360 clips, 540 segments, and video re-encoded rather than stream-copied — completed in 16.82 minutes with eight workers, exact 108,000 frames, and clean scratch. Direct full-frame video re-encoding later reduced it to 15.57 minutes with a byte-identical file; a 60-second video-only gate fell from 10.65 to 7.61 seconds. The 10-minute one-layer gate improved from 211.8 s to 192.6 s by reusing loaded composition sessions across segments. The fast path copies full-frame, untransformed video whose source matches the project format and whose source keyframes (I-frames) fall on segment boundaries; media that needs scaling or transforms is re-encoded and adds cost not included in that projection. Timeline clip keyframes add per-frame filter expressions and, for animated opacity or scale, an alpha-mask pass per affected layer; the keyframe benchmark reports current timings and is not part of the 60-minute projection.

The renderer uses a bounded segment plan, a worker pool, and a scratch budget. It never publishes a partial output, and it cleans scratch on success and failure. Segment boundaries preserve timeline frame order and timing; the final audio mix is muxed once.

`check` and `still` use the same clip capture and timeline composite path for requested frames. `check` evaluates every timeline frame; on long timelines this is a validation cost, not a render. A static composition has one state and is inspected once. `still` captures one or more requested frames as PNGs without encoding a video; a static composition exposes only frame 0.

## 5. Audio and output

A timeline has one audio mix. It combines:

- composition audio clips declared inside composition clips, shifted and trimmed by the clip's source range;
- embedded video audio from composition clips and media video clips, unless muted;
- timeline audio clips on audio tracks;
- audio from nested timeline clips, recursively.

Per-clip gain and mute, per-audio-track gain and mute, and composition-level volume apply. Audio fades are deferred. The mix is produced once with FFmpeg and muxed into the final output. Preview mixes the same resolved clips in the browser for monitoring; it is not the production source of truth.

Audio, video, and transcript `src` values resolve from the project root. The controller `src` and ordinary HTML asset URLs resolve relative to the composition URL.

Generated speech behaves like any other audio clip. Frameyard does not automatically time-stretch it, change timeline duration, or regenerate it to fit. `check` reports clip durations and overrun warnings so users and agents can revise text, timing, or the timeline deliberately.

Timelines and animated compositions produce MP4, MOV, MKV, or WebM files. The default is MP4 with H.264 video and AAC audio; HEVC and VP9 are opt-in, and WebM is VP9 with Opus. HEVC in MP4 and MOV keeps the `hvc1` sample entry and is not playable in browsers without platform HEVC decoding. Frameyard exposes only a small set of validated encoding options, not arbitrary FFmpeg arguments. A static composition produces one PNG and uses no encoder.

`render --frames <spec>` limits video output to an inclusive frame range. Video requires a contiguous range; arbitrary lists are supported by `render --sequence <dir>`, which writes PNG sequences. `--scale` from 0.25 to 1 captures compositions and timeline stages at the scaled format, with even-sized output; delivery encoding does not apply a final scale pass. A range shifts and trims the audio mix to the same output window. A static composition rejects both flags.

PNG output through `still`, including a bounded set of inspection frames, remains a debugging artifact. `render --sequence` is the production image-sequence path; a standalone static composition still renders to one PNG.

A render fails immediately on an uncaught exception, unhandled rejection, required-asset failure, invalid composition output, segment encoding failure, or scratch failure. Diagnostics identify the timeline, clip, segment, and, where applicable, the frame. The CLI exits nonzero, cleans temporary files, and never reports a partial video as successful. Existing output files are not overwritten unless explicitly requested.

## 6. CLI, tooling, and package boundaries

Project and composition commands are:

- `init [directory] [--local-models]`: scaffold a timeline-first project with a composition, a one-clip timeline, a project format, an agent guide, a `.gitignore` for `out/`, and a private `package.json` with pinned `dev`, `check`, `render`, and `still` scripts. Without a directory, an interactive terminal prompts for a project name (default `my-video`) and creates that directory; non-interactive and `--json` runs use `my-video`. `--local-models` also installs the optional workspace policy, OpenCode permissions, and Pi settings.
- `dev`: start the preview with composition and timeline modes.
- `render <id> [--out video]`: render a timeline, an animated composition, or a static composition. Timeline renders accept `--workers <n>` and `--scratch <dir>`; composition renders accept `--concurrency <n>` from 1 to 16. `--container <mp4|mov|mkv|webm>` and `--codec <h264|hevc|vp9>` select the delivery pair (MP4/H.264 by default; WebM defaults to VP9), and `--encoder <auto|software|nvenc|qsv>` selects how it is encoded; `auto` is the default and probes NVENC then Quick Sync before falling back to software. The output extension must match the container. The default output is `out/<id>.<ext>`. `--frames <spec>` limits video to a contiguous inclusive range and shifts/trims audio; `--sequence <dir>` writes PNGs for arbitrary frame lists; `--scale` (0.25-1) captures compositions and timeline stages at the scaled format. A static composition writes `out/<id>.png` and rejects `--container`, `--codec`, `--encoder`, `--concurrency`, `--frames`, and `--scale`. The JSON result is a discriminated union with `kind: "video"`, `kind: "image"`, or `kind: "sequence"`.
- `context`: print a read-only project digest with the format, composition metadata, prop keys and types, controller declarations, timeline clip summaries, unique assets, installed fonts, diagnostics, active policy, and next commands. It never launches Chromium.
- `lint <id>`: run static validation, timeline resolution, scene and keyframe projection for every timeline frame, a controller determinism scan, and media metadata probing without Chromium. It does not run `validateProps` or composition runtime; `check` remains the full gate.
- `inspect <image>` and `compare <first> <second>`: decode images through FFmpeg and report blank/alpha/color/content facts or a pixel and 3×3 region diff. These are text-only inspection aids, not a substitute for viewing a still.
- `add --list`, `add local-models`, `add <composition|timeline> <id> --template <name>`, and `add recipe <recipe-id> --id <project-id>`: list templates, recipes, and scaffolds; install the optional local-model host scaffold; write a valid template entry; or install a recipe bundle with a composition, timeline, props, and README. The initial recipes are `lower-third`, `title-card`, `captions`, `audio-visualizer`, `countdown`, `stat-card`, `product-showcase`, `logo-sting`, `split-screen`, and `slideshow`. Every form prints the exact `fy.config.js` registration snippet. `add` never edits the config and never overwrites an existing file or registered id.
- `asset add <url> --out <path>`: download an HTTPS image, video, or audio asset into the project (loopback HTTP is allowed for tests), verify an optional `--sha256`, publish atomically, and record `src`, `sha256`, `bytes`, `source`, and `fetchedAt` in the `assets` array of `fy.assets.json`. Unsafe URLs, paths outside the project, and unsupported extensions fail before writing. `--force` requires the `full` policy tier.
- `explain <code>`: print the cause, a minimal failing example, the corrected example, and a documentation link for a stable diagnostic code. `explain --list` lists every code with a short summary. Diagnostics and error envelopes may carry an optional `fix` object with `kind`, `message`, `from`, `to`, `patch`, `command`, and `docs`; fixes are advisory and are never applied automatically.
- `font search`, `font add <id>`, `font add --file`, `font add --url`, `font list`, `font verify`, and `font remove <id>`: search Fontsource, vendor a Fontsource/local/URL font into `assets/fonts/<id>/`, record it in `fy.fonts.json`, inspect its license/hash status, or remove it. The server serves the generated `@font-face` sheet at `/__frameyard/fonts.css` and injects it into composition documents. Fontsource installs pin `npmVersion` and vendor the package license; URL imports require HTTPS outside loopback tests and record an unknown license only in the `full` tier.
- `check <id>`: run static validation, then validate configuration, props, assets, media, audio, and transcript requirements, load the target, and evaluate every frame without capturing or encoding. A static composition is loaded and inspected once and returns `kind: "static"` with `framesChecked: 1`.
- `still <id> --frame <spec>`: capture one or more requested frames as PNGs through the clip capture and timeline composite path. A static composition exposes exactly frame 0. `<spec>` is a frame number (`42`), an inclusive range (`2-12`), or a comma-separated list (`0,118-126,240`); duplicates are removed preserving the first occurrence, input order is preserved, and one invocation captures at most 32 unique frames. There is no step or sequence mode. A single frame keeps the existing `--out <file.png>` behavior; multiple frames use `--out <directory>` and write `still-<id>-<frame>.png` files, defaulting to the current working directory. Frames and output conflicts are validated before Chromium, all frames are captured to temporary files before publication, and a failed capture publishes no files. JSON results add `frames` and keep the singular `frame` and `path` only when one frame was captured. See [ADR 0013](./adr/0013-capture-bounded-multi-frame-stills-for-inspection.md).
- `doctor`: inspect core requirements, optional integrations, the active resource policy, installed font manifests, and basic CPU/load/memory resources without repairing or downloading anything.

`lint`, `check`, `still`, and `render` run a Node-side static validation; `check`, `still`, and `render` then launch Chromium. For a timeline it validates the JSON document, tracks, clips, references, nested timelines, cycles, frame-rate compatibility, overlaps and transitions, source bounds, media, transforms, keyframes, audio settings, props, and every referenced composition. Static validation and the composition host read the composition grammar through one browser-safe reader with document and fragment scopes. Timeline diagnostics carry stable codes and optional source locations or JSON paths, and composition diagnostics from inside a timeline carry the clip and track context.

Local asset-production commands are `tts` and `transcribe`. Every non-interactive command supports `--json` with stable result and error schemas. Structured results go to stdout; human diagnostics and inference progress go to stderr, and `check` and `render` accept `--no-progress` to silence progress without changing the result. Project font acquisition is a separate authoring operation: `fy.fonts.json` records vendored files, licenses, and SHA-256 values; there is no shared font cache and no runtime font CDN. Fontsource search and download use the public Fontsource API and pinned CDN versions; local files and explicit HTTPS URLs cover other sources. The generated `@font-face` sheet is served at `/__frameyard/fonts.css` and injected before author styles.

A workspace `fy.policy.json` gates expensive operations. The nearest file from the working directory upward applies, independent of `fy.config.js`; `FRAMEYARD_POLICY` replaces it. `light` allows one still frame and blocks `check`, `tts`, `transcribe`, and `render`; `authoring` allows four still frames and `check` at low priority and blocks the three heavy operations; `full` allows everything up to the 32-frame still cap. Font list/verify/search are available in every tier; `font add` requires authoring or full; `font remove`, `font add --force`, and an unlicensed `font add --url` require full. A file can only tighten its tier. `--profile shared-cpu` caps timeline workers at two and composition concurrency at one and lowers process priority. `tts`, `transcribe`, and `render` accept `--dry-run`, which validates inputs and returns `plan`, `commandLine`, `prerequisites`, and `blockers` without writing outputs, loading a model, launching Chromium, or encoding. The policy is a guardrail, not a security boundary; see [ADR 0022](./adr/0022-gate-heavy-operations-with-a-workspace-resource-policy.md).

The built-in server serves native ES modules, static assets, composition entries, timeline documents, and the timeline preview host. It wraps each configured composition fragment in the fixed document shell, injects the framework import map and composition host, and serves an inline controller through a virtual module URL. It performs no dependency pre-bundling. Third-party libraries must initially be browser-ready ES modules referenced explicitly. Running through the CLI server is required; direct `file://` execution is unsupported for deterministic preview or rendering.

Frameyard uses one repository and one publishable npm package with four internal layers:

1. Shared composition and timeline contracts and HTML/JSON parsing
2. Browser composition host and timeline preview host
3. Node-based static validation and segmented timeline renderer
4. Node-based CLI, asset production, and doctor

These layers have clean internal boundaries but no public plugin API. FFmpeg is required for encoding, probing, media decoding, audio mixing, and timeline compositing. Skia is not required in 0.6. The project supports the current active Node.js LTS; Linux is the reference and CI platform, while macOS and Windows remain best-effort until covered by real rendering tests.

## 7. Official agent skill

Frameyard ships an optional, host-neutral agent skill with a `SKILL.md`, supporting references, and thin scripts. The npm package includes skill files matching its API version, and documentation explains host-specific installation or referencing. 0.6 does not add a skill-installer command.

The skill:

- Uses the normal project format, HTML composition contract, JSON timeline contract, optional controller, and CLI available to humans.
- Does not introduce an agent-only runtime, MCP server, hosted control plane, or separate rendering API.
- Triggers for Frameyard authoring and operation rather than claiming to be a general-purpose media-generation skill.
- Uses Frameyard's audio wrappers instead of invoking `qwen-tts`, `sherpa-onnx-offline-tts`, or `whisper-cli` directly.
- Includes references for deterministic HTML authoring, timeline JSON authoring, tracks, clips, source ranges, props, media, nested timelines, static transforms, clip keyframes, clip transitions, audio, validation, diagnostics, common mistakes, subtitle and karaoke recipes, JSON command results, long-form worker/scratch settings, and failure recovery, plus a compact quick reference for limited-context hosts.
- Invokes speech synthesis or transcription only when requested or explicitly approved as part of the brief.
- Does not overwrite or regenerate existing generated assets without permission.
- Uses `lint` for the edit loop, `check` for the full gate, and `--dry-run` to hand off heavy operations when the workspace resource policy blocks them.
- Respects `fy.policy.json` and does not edit the policy file, host configuration, or skill source.
- Runs `check`, inspects representative `still` images when the host supports image viewing, and discloses when visual inspection was impossible.
- Does not claim success when checks fail or rendering is partial.

A successful agent workflow preserves and reports the source project, timeline document, props, generated assets, provenance manifest, validation results, and final video path. The user must be able to inspect, modify, and reproduce the result rather than receiving only an opaque MP4.

Local-model host setup is optional and separate from a Frameyard project: `scaffolds/local-models/` contains an `authoring` policy, OpenCode permissions, and Pi settings that a workspace can copy when a local model and rendering share the machine. Without the scaffold, the CLI defaults to `full` and no host configuration applies.

## 8. Local speech synthesis

The `tts` command integrates [`qwentts.cpp`](https://github.com/ServeurpersoCom/qwentts.cpp) through its external `qwen-tts` executable. It does not link the native library or require the upstream server.

The qwen engine supports CustomVoice mode only:

- A named speaker is required.
- An optional style instruction and language may be supplied.
- Reference-audio voice cloning and free-form VoiceDesign are deferred.
- Text is supplied by `--text-file` or stdin.
- Talker GGUF, codec GGUF, and output paths are required.
- One invocation produces one frozen 24 kHz mono WAV from one complete text input.
- Automatic long-text chunking, streaming, and alternative audio formats are deferred.

`tts --engine supertonic` integrates [`sherpa-onnx`](https://github.com/k2-fsa/sherpa-onnx) through its external `sherpa-onnx-offline-tts` executable and the Supertonic 3 model archive:

- The engine covers 31 languages and requires one of their language codes, a numeric speaker id, and a directory containing the seven model files.
- The engine writes its native WAV; Frameyard normalizes it to the same frozen 24 kHz mono WAV contract with FFmpeg and records `sourceSampleRate` and `sourceChannels` in the manifest.
- The manifest records the seven model identities, the pinned sherpa-onnx revision, and the model archive name.
- Supertonic expression tags belong in the text; the qwen-only style and device options are rejected for this engine.
- The upstream Supertonic repository is archived and its weights use the OpenRAIL-M license. Users acquire the executable and weights explicitly; Frameyard does not redistribute them.

Users acquire and provide models explicitly. Frameyard does not build `qwentts.cpp` or `sherpa-onnx`, download or redistribute models, or imply that upstream code licenses settle model-weight licensing. Executable resolution uses an explicit option, then environment configuration, then PATH.

## 9. Local transcription and timed text

The `transcribe` command integrates [`whisper.cpp`](https://github.com/ggml-org/whisper.cpp) through its external `whisper-cli` executable. Before transcription, Frameyard uses FFmpeg to normalize source audio or video to 16 kHz mono PCM WAV, avoiding dependence on optional upstream decoder builds and inconsistent input-format documentation.

Users provide a Whisper GGML model explicitly. The command requires source and output paths and supports optional word timings through `--words` and derived subtitle exports through `--export srt,vtt`. Executable resolution follows the same option, environment, then PATH order as speech synthesis.

The canonical artifact is a versioned Frameyard JSON document containing:

- Full text
- Source identity and content hash
- Language when known
- Timed segments
- Optional word timings

All timestamps are integer milliseconds relative to the source audio, not timeline or composition frame numbers. A controller converts them using the audio clip's start frame, source trim, and the composition frame rate.

Compositions declare required transcript assets with `<fy-transcript>` elements:

```html
<fy-transcript src="assets/voice.transcript.json" words></fy-transcript>
```

`check` and production validate declared transcript files before frame production. `words: true` requires measured word timings and fails when they are unavailable; it never triggers interpolation.

SRT and VTT are derived exports, not the canonical contract. Word-level karaoke requires actual word timings and fails validation when they are unavailable. Frameyard never fabricates word timings by interpolating segment timestamps and never executes Whisper's generated bash/FFmpeg karaoke script.

The official skill documents seek-safe subtitle and karaoke recipes. Compositions retain responsibility for visual presentation; 0.6 has no built-in subtitle renderer and does not automatically burn captions into videos. Karaoke presentation uses the optional controller.

## 10. Generated assets and inference operation

Speech synthesis and transcription are separate asset-production operations that complete before a timeline or composition is loaded or rendered. Their outputs are ordinary local project assets. Once those assets are frozen, ordinary authoring, preview, checking, and rendering require neither AI executable nor model.

Remote images, video, and audio are acquired explicitly with `asset add`. They are hashed, published into the project, and recorded in the `assets` array of the same provenance manifest. Rendering never fetches a remote URL.

Both integrations are optional and local-only, with no cloud fallback. Network activity needed to acquire tools or models is a separate explicit setup operation, never a hidden side effect of generation or rendering.

Generated artifacts follow a shared contract:

- Outputs are written atomically to explicit paths.
- Existing outputs are not overwritten unless `--force` is supplied.
- A versioned project-local provenance manifest records artifact content hashes, generator details, model identities, and parameters. The default manifest is `fy.assets.json` in the project root; `--manifest` selects another path.
- Transcription provenance also identifies the source asset by content hash.
- Partial operations leave neither apparently valid artifacts nor manifest entries.
- `doctor` validates executables, model readability, capabilities, and supported integration versions when the upstream CLI exposes a version, without modifying the environment.

Each operation runs one inference subprocess, and the official agent workflow executes inference sequentially to avoid unexpected CPU/GPU contention. There is no arbitrary fixed timeout. Cancellation terminates the child process and removes partial outputs.

Release documentation must identify the exact `qwentts.cpp`, `sherpa-onnx`, and `whisper.cpp` revisions against which the wrappers are tested. Frameyard does not claim compatibility with arbitrary upstream revisions.

## 11. Verification strategy

Tests prioritize public behavior and end-to-end evidence over implementation-only unit coverage:

- HTML compositions validate metadata, default props, props schemas, bindings, conditionals, repeats, and controller declarations, including inline/external parity and the exactly-one-controller rule.
- Static composition validation catches metadata, root/controller count, binding, animation, script, element, and asset-reference errors before Chromium. It resolves declared format values against the project format and reports an unresolved format to the command rather than the document. A composition with neither time attribute is static; `fps` without `duration-in-frames`, `data-fy-anim-*`, media, and transcripts on a static composition are errors.
- Timeline JSON validation catches schema, track, clip, reference, cycle, frame-rate, overlap, transition, bounds, media, transform, audio, and props errors before Chromium.
- Diagnostics carry stable codes and source locations or JSON paths, plus an optional advisory `fix`; `explain <code>` and `explain --list` expose the same code catalog. JSON results expose the composition or timeline entry, clips, tracks, and top-level diagnostics.
- Sequential, individual, random-order, and parallel composition renders produce equivalent images; timeline segment workers produce ordered output and identical captured composition frames.
- Determinism checks compare captured composition pixels or stills. The final encoded bytes and the FFmpeg composite versus Chromium preview are not reproducibility oracles.
- Preview and renderer use the same composition source and host behavior; timeline preview uses the same active clip hosts.
- CSS, controller JavaScript, SVG, Canvas, WebGL, embedded video, and audio frames seek correctly.
- Frame-scheduled `data-fy-anim-*` animations, named animation presets, and frame-state CSS variables produce the expected frames.
- Timeline capture preserves alpha for transparent compositions; FFV1 intermediates decode pixel-identically to the captured frames.
- Timeline segment encoding, ordered concatenation, global audio mix, and scratch cleanup produce the expected output dimensions, frame count, duration, and audio stream.
- Nested timelines preserve group opacity and transform semantics; cycles fail static validation.
- Media clips trim and fit deterministically; images require durations; source overruns fail.
- Props overrides for timeline composition clips merge over clip props and are reflected in the render. Schema defaults and validation apply to composition props before Chromium and again in the host.
- `check` exercises every animated frame and inspects a static composition once; it also evaluates every keyframe channel at every timeline frame. `still` follows the clip capture and timeline composite path. A static composition render captures one PNG; a timeline reuses one static image capture per props variant.
- The 10-second and 60-second long-form benchmarks record capture, FFV1, composite, encode, disk, worker, and audio numbers. Continuous three-layer runs measured 52.4 s and 58.5 s for 60 s of timeline and are documented as worst-case (~1× real time). The representative 50/50, 60/30/10 occupancy gate measured 29.39 s for 60 s with four workers and a 1080p media fast path, extrapolating to about 29.4 minutes for 60 minutes with exact 1800-frame output. The full 60-minute composition-only gate rendered 108,000 frames in 37.28 minutes with four workers before streaming and the direct-segment fast path; the same gate completed in 19.83 minutes with eight workers after ADR 0024 and 18.78 minutes after session reuse (ADR 0026), with exact output, clean scratch, and a byte-identical file. The ten-minute gate projects about 24 minutes at four workers. Independent layers are captured concurrently under a global session limit (ADR 0025); the two-layer PIP 60-second gate fell from 59.60 s to 43.78 s with parallel captures. A full-frame composition base plus a static composition overlay encodes through dual image pipes (ADR 0027); the full-frame 60-second workload fell from 53.27 s to 34.62 s, the PIP 60-second workload from 43.78 s to 33.90 s, and the full two-layer 60-minute gates completed in 29.69 minutes (full-frame) and 25.75 minutes (PIP) with eight workers. The representative 60-minute 50/50 production gate completed in 16.82 minutes with eight workers, exact 108,000 frames, clean scratch, and no video stream-copy; direct full-frame video re-encoding reduced it to 15.57 minutes with a byte-identical file. Loaded composition sessions are reused across segments (ADR 0026); the 10-minute one-layer gate fell from 211.8 s to 192.6 s, and the full gate opened eight sessions instead of 360.
- Golden-frame tests cover representative composition and timeline visual behavior.
- Normal CI uses fake `qwen-tts`, `sherpa-onnx-offline-tts`, and `whisper-cli` executables and small fixtures to verify arguments, artifacts, manifests, cancellation, and errors without model downloads or GPU hardware.
- Real-model integration tests are explicitly opt-in and use documented upstream revisions.
- Agent-workflow evaluations verify source preservation, provenance, validation, still inspection behavior, failure reporting, and final renders.
- Local-model evals are opt-in and run against a llama.cpp router: eight authoring tasks, first-pass lint, repair turns, token and wall-time counts, and sampled server CPU/RSS/GPU. They exercise the same quick reference and CLI as an agent, never render, and stay outside `pnpm check`.

## 12. Deferred

These are scope boundaries, not permanent rejections:

- Animated blend modes, filters, masks, and audio fades
- Full visual timeline editing, drag-and-drop, clip handles, and undo/redo
- Timeline-level variables and prop overrides for compositions inside nested timelines
- Track solo and video-track visibility
- Per-timeline formats and frame-rate conversion/retiming
- Persistent clip caches; the segmented renderer cleans its intermediates
- GPU compositing and codecs beyond H.264, HEVC, and VP9
- Hosted rendering, collaboration, and asset marketplaces
- Cloud generative-AI services, text-to-video generation, and image generation
- `qwentts.cpp` reference-audio voice cloning and VoiceDesign
- Automatic long-text chunking, streaming speech synthesis, and alternative generated-audio formats
- Built-in subtitle rendering, automatic caption burn-in, and declarative karaoke elements
- Nested `data-fy-repeat` scopes and a general template language
- Declarative JSON Schema validation
- A shared font cache, hosted font catalog, or first-class Google Fonts/Fontshare/Bunny providers; Fontsource plus local/HTTPS imports cover acquisition
- Typography roles, font-pair presets, a preview font picker, and variable axes other than `wght`
- Arbitrary executable scripts in composition HTML
- Automatic upstream builds, model downloads, weight redistribution, and environment repair
- Agent-only runtimes, MCP servers, hosted agent control planes, and host-specific skill installers
- Automatic idle scheduling, job queues, and OS-level resource enforcement; the workspace policy is a guardrail, not a sandbox
- React or other UI-framework adapters in the core
- Public plugin APIs and a broad integration ecosystem
- Dynamic composition or timeline metadata derived from props
- Live streams, remote media, and other visual sources that cannot be deterministically seeked
- Dynamic per-frame asset loading or AI inference
- Unbounded batch still capture; `still` accepts at most 32 inspection frames per invocation. Use `render --sequence` for production image sequences.
- Additional final-video formats, GIF/audio-only output, HDR/ProRes, and arbitrary FFmpeg argument passthrough
- Audio, transcripts, or embedded video in a static composition; use a timeline
- A `--video` escape hatch for static composition renders; use a timeline image clip
- Exporting a fully static timeline as a PNG
- Recursive static optimization of nested timelines
- Built-in TypeScript transpilation and npm dependency optimization
- Rendering untrusted compositions
- Bit-identical cross-platform encoded output or AI regeneration
- A minimum production rendering-speed guarantee for compositions or timelines
