# Frameyard blend example

A 6-second, 1920×1080, 30 fps timeline that demonstrates static CSS blend
modes on composition and video clips. Four video tracks build one frame:

- `v1` **backdrop** — an opaque HTML composition with a grid, concentric rings,
  and a dark vignette.
- `v2` **aurora** — a transparent HTML composition with three blurred color
  blobs. Its clip uses `blend: "screen"` for the full 6 seconds.
- `v3` **ink** — a local 1280×720 H.264 clip scaled to fill the project frame.
  Three touching clips play the same source with different static modes:
  `multiply` from 0–2 s, `soft-light` from 2–4 s, and `overlay` from 4–6 s.
- `v4` **labels** — a transparent HTML composition in normal mode. It names the
  active modes and draws a progress bar from the `--fy-progress` frame-state
  variable.

The aurora is transparent, so `screen` blends only where its blobs have alpha.
The video is opaque, so its whole scaled frame participates in the blend. The
labels layer stays in `normal` mode so the copy remains readable.

Blend modes are static per clip. The example uses consecutive clips on `v3` to
show three modes in one timeline; it does not animate `blend` itself. Only the
separable CSS modes are supported: `normal`, `multiply`, `screen`, `overlay`,
`darken`, `lighten`, `color-dodge`, `color-burn`, `hard-light`, `soft-light`,
`difference`, and `exclusion`. `hue`, `saturation`, `color`, and `luminosity`
are rejected.

Preview composites with Chromium `mix-blend-mode`; production uses FFmpeg's
`blend` filter plus an alpha mask. The preview stage stacks by track order and
is isolated from the preview chrome. Small scaling, alpha, and color differences
between preview and the final encode are expected.

## Files

```text
examples/blend/
  compositions/backdrop.html   opaque base composition
  compositions/aurora.html     transparent screen layer
  compositions/labels.html     transparent copy and progress layer
  timelines/blend.timeline.json
  assets/ink.mp4               procedural 3-second source clip
  scripts/make-ink.sh          regenerate assets/ink.mp4
  video.config.js
```

The timeline lives in `timelines/blend.timeline.json`; the project format and
entries are fixed in `video.config.js`.

## Commands

From the repository root:

```sh
pnpm build
node dist/cli.js check blend-timeline --project examples/blend
node dist/cli.js still blend-timeline --frame 30 --project examples/blend --out blend-multiply.png
node dist/cli.js still blend-timeline --frame 90 --project examples/blend --out blend-soft-light.png
node dist/cli.js still blend-timeline --frame 150 --project examples/blend --out blend-overlay.png
node dist/cli.js render blend-timeline --project examples/blend
node dist/cli.js dev --project examples/blend
```

`render` writes `out/blend-timeline.mp4` inside the project by default. Use
`--out <file.mp4>` to choose another path. `dev` lists the compositions and the
timeline in the preview.

## Source clip

`assets/ink.mp4` is a 3-second, 1280×720, 30 fps rotating gradient with a silent
AAC track, generated by FFmpeg. Regenerate it with:

```sh
bash examples/blend/scripts/make-ink.sh
```

Pass an output path as the first argument to write elsewhere. Replace
`assets/ink.mp4` with any local, seekable MP4 or WebM that is at least 3 seconds
long; remote URLs and live streams are not supported. If you use a different
length, update the clip durations and source in-points in the timeline.
